# Möbius System Boundaries

> Status: **Canonical scope boundary**

Möbius governs software-development change. It is deliberately not the universal control plane for all AI execution.

## 1. Möbius owns

- development-time architecture governance;
- repository-aware change planning;
- Architecture Contracts;
- Plan Gates and Architecture Gates;
- engineering evidence collection;
- repository/worktree/PR governance;
- coding-runtime adapters;
- architecture-debt and ADR memory;
- exact-state review and merge authorization workflows.

## 2. Möbius does not own

- frontier-model intelligence;
- generic production inference routing;
- organization-wide AI policy outside software development;
- computational-capital allocation across arbitrary workloads;
- cross-organization trust/transaction protocols;
- financial-domain logic;
- acquisition/monitoring product logic;
- learning/mastery domain logic.

## 3. Rasputin boundary

Rasputin is the broader runtime sovereign control and trust plane.

```text
Rasputin
  governs AI execution at runtime:
  authority / policy / computational capital / tools /
  verification / audit / inter-org trust

Möbius
  governs software change at development time:
  architecture / change contracts / evidence / repo /
  agent engineering workflows / merge authority
```

Future integration may allow Möbius to request runtime policy/capabilities from Rasputin, but Möbius must remain independently usable.

## 4. FlowTracer boundary

FlowTracer owns monitoring/acquisition product behavior. Möbius may govern how FlowTracer code evolves, but must not absorb FlowTracer business logic.

## 5. Gallop boundary

Gallop owns learning evidence, progression, mentorship, and mastery logic. Möbius protects Gallop architecture but cannot become the learning engine.

## 6. FinTerminal boundary

FinTerminal owns financial application behavior. Möbius can detect architecture debt and coordinate refactoring without becoming the financial application kernel.

## 7. Execution-runtime boundary

Codex, Claude Code, Astra, Hermes, and future coding agents are execution runtimes.

They may:

- inspect code;
- propose plans;
- implement admitted changes;
- run validations;
- report evidence.

They may not implicitly:

- rewrite Architecture Contracts;
- waive violations they introduced;
- redefine merge/release authority;
- convert passing tests into architecture approval.

## 8. Product identity

Möbius should be described as:

> **Architecture & Development Governance Control Plane for AI Engineering**

not as:

- a multi-agent swarm;
- a Codex thread manager;
- an autonomous software factory;
- a generic model router;
- a replacement for Git/CI/IDEs.

Those may be components, integrations, or execution strategies, but they are not the product definition.
